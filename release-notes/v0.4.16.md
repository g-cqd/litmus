# litmus 0.4.16 (from 0.4.15)

Shorter timeouts. A mutant that hangs now waits a deadline based on how long this run's other mutants took, not on the whole baseline's wall time, which on a simulator is mostly the startup of every test module. The ExampleApp fixture on a simulator now takes 316 s instead of 927 s, with the same verdict for every mutant.

## Behaviour

- **Deadlines from this run's own timings.** Each first run of a mutant that ends on its own (passed or failed) is a sample, kept per run kind. A narrowed run (named reaching tests) is one kind; each set of covering test modules is another. Once a kind has 8 samples, a run of that kind gets `timeoutFactor` × their 95th percentile + 2 s. That deadline is never less than `--minimum-timeout` and never more than the deadline the baseline sets. A rerun alone gets twice that.
- Timeouts and crashes are never samples, so one timeout never lengthens the next. Until a kind has 8 samples, its runs keep the baseline's deadline, as before.
- On the benchmark's iOS app, five hanging mutants used to take about 3,100 s of 3,450 s of test time. On the ExampleApp fixture, the endless-loop mutant now times out after 136 s instead of 588 s.
