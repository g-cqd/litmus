# litmus 0.5.0 (from 0.4.16)

Completes Phase D with shared-process execution (`--shared-process auto|on|off`, default `auto`) for macOS SwiftPM and iOS Simulator unit test bundles. Narrowed Swift Testing runs execute inside long-lived helper processes that keep the test bundle loaded and switch mutants through an `mmap` control page; survivors, XCTest, crashes, timeouts, and process-cached switches (`static let`, `lazy`) still run in fresh processes so verdicts match isolated runs.

## Behaviour

- **Shared control page (`LITMUS_SHARED_MAP_<token>`).** Fixed 8 KiB `mmap` layout with magic header, active mutant id + flag, hit counter, and per-slot evaluation counters. Without a valid page, schemas use `LITMUS_ACTIVE_ID_<token>` unchanged.
- **Process-lifetime classification.** Each worker runs two unmutated passes on startup; switches evaluated during load or an unequal number of times across passes are marked `processCached` and always run in fresh processes.
- **Soundness rules.** Shared workers decide kills only when `activeHits > 0` and the mutant's reaching tests pass again unmutated in the same worker. Narrowed passes hand off directly to the fresh full-module survivor recheck rather than running twice; workers recycle every 32 mutants or on any state doubt, crash, or timeout.
- **Simulator serve loop.** `SimulatorHelper` adds `--serve` over host FIFOs and reports its inner PID on `ready` so terminating a worker kills both `simctl spawn` and the simulator helper process.
- **`auto` break-even rule.** Engages per batch when there are at least 8 covered mutants, process spawn is at least 0.25 s, and saved spawns exceed worker startup + classification cost. Stays off on fast macOS SwiftPM bundles (~0.1 s spawn) and engages on simulator runs (~24% faster test phase on the 164-mutant `Transit` benchmark, 164/164 verdicts identical).
