# litmus 0.9.0 (from 0.7.1)

Phase F2 completion: UI-test mutants share one `xcodebuild` session per batch, and the XCUITest activation bridge is checked end to end on a project with a UI-test target.

The v0.8.0 tag never published: the source split had left the duplication baseline behind, and CI failed on it. Its Phase F1 changes ([v0.8.0 notes](v0.8.0.md): `Button` and gesture actions, `neutralize-view-modifier`, `remove-accessibility-metadata`, sources split into files of at most 300 lines) ship in this release.

## Behaviour

- UI sessions: with UI test bundles under `xcodebuild` on one destination, a batch's first runs go through one `xcodebuild test-without-building`. Its format-2 `.xctestrun` has one test-plan configuration per mutant, each with that mutant's `LITMUS_ACTIVE_ID`, coverage directory and `TMPDIR` in `UITargetAppEnvironmentVariables`. Results are read per configuration from `xcresulttool get test-results tests`.
- A session decides survivors only. Failures, crashes and timeouts are rerun fresh and alone, as before. A configuration missing from the results, or one whose test population differs from the others, runs fresh. Session times never set fresh-run deadlines.
- Measured on `bench/Transit` (new `TransitUI` scheme: the app's `TransitUITests` only; iPhone 18 Pro simulator, `--operators ui`, 9 mutants): test time went from 292 s to 190 s with identical verdicts (4 killed, 5 survived). The kills' fresh confirmation reruns are most of what remains.
- The v0.7 XCUITest bridge, checked on the same run: `remove-view-action` on the `Buy ticket` action, `negate-disabled` on its `.disabled(...)`, and removal of the button and of the message text are killed by `TripUITests`.
