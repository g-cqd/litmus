# litmus 0.4.12 (from 0.4.11)

Updates transitive `swift-crypto` to 5.2.0 (resolving GHSA-c24m-vphm-p22w and GHSA-rch3-xxjq-365j), adds `swift-ci`-managed Dependabot updates with a 7-day release cooldown, enables Semgrep and CodeQL code scanning, enforces the `Security · Advisories` gate in CI, and ships nested mutation schemas, single-pass FIFO `--per-test-reach`, `@_silgen_name` schema runtime bindings, and eight opt-in mutation operators.

## Flags

- `--operators`: adds opt-in `replace-stdlib-semantic`, `remove-normalization`, `replace-optional-chain`, `return-boundary`, `return-constant`, `empty-body`, `empty-closure-body`, and `remove-switch-case`.
- `--arid-call` and `--exclude-declaration` (and matching `.litmus.json` keys).
- `--no-recheck-survivors`: opt out of re-verifying narrowed survivors against all covering test modules.

## Behaviour

- Inside-out nested schema rendering (`RegionForest`, default batch size 256) and static `SwiftParser` verification of rendered schemas.
- Single-pass FIFO `--per-test-reach` interleaving during the control run, plus survivor recheck across covering test modules.
- `@_silgen_name` C runtime bindings instead of injected `import Foundation`.

## Findings that may appear

Unknown operator names in `@lm:accept` / `@litmus:accept` emit a `PlanNote` warning; opt-in operators emit additional mutants when enabled.

## Findings that may disappear

False narrowed survivors caused by per-test reach narrowing are caught by `recheckSurvivors`.
