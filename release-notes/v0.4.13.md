# litmus 0.4.13 (from 0.4.12)

Pinpoints unviable mutants on nested single-line schemas by compiler diagnostic `(line, column)` byte offset, skips guaranteed constant-folded integer overflows and element-form `contains(_:)` swaps, avoids duplicate literal/relational return mutations, and defers multi-simulator pool creation until `xcodebuild` is actually selected so `simulator-direct` runs avoid cold simulator boots.

## Behaviour

- `RenderedSchema.branchBytes` and `CompilerDiagnostics` match compiler error `(line, column)` offsets against each mutant's narrowest replacement branch before falling back to line-range matching, isolating an unviable mutant on a nested single-line schema in one step instead of bisecting all siblings and ancestors on that line.
- `replace-arithmetic` skips guaranteed compile-time constant-folded integer overflows on `.max` / `.min` (such as `Int.max / 2` to `Int.max * 2`).
- `replace-stdlib-semantic` restricts `contains` <-> `allSatisfy` swaps to predicate forms (trailing closures and `where:` arguments), leaving element-membership calls such as `(0...100).contains(x)` untouched.
- `return-boundary` skips numeric/boolean literals and `return-constant` skips binary relational expressions already covered by `replace-relational`.
- `RunSession` probes `simulator-direct` on the destination simulator before creating `--simulators N` pools, probes every fleet device with a retry on cold-boot `SIGTERM`, and under `simulator-direct` reboots owned simulators only on `.timedOut` rather than isolated child `SIGTRAP`s.

## Findings that may disappear

- Guaranteed compile-time constant-overflow `unviable` entries (such as `Int.max * 2`) and element-form `contains(_:)` `unviable` entries are no longer emitted.
- Duplicate literal `return-boundary` (`(0) + 1`) and relational `return-constant` mutations are omitted.
