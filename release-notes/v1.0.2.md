## Behaviour

- Under `xcodebuild`, `--memory-limit` (default 4096 MiB) no longer applies. The limit covers only `xcodebuild`'s own session; the test hosts run in the simulator, outside it. So it could not catch a mutant's runaway allocation, and only stopped `xcodebuild` as its memory grew with the suite's output. On an app with fourteen test bundles, this ended the unmodified test run after four bundles, every time, with `xcodebuild exit 143`. SwiftPM and simulator-helper runs keep the limit, where it covers the test process itself.
- When a run's result bundle has no summary, the error now includes why its supervision stopped it, if it did.

## Findings that may appear

- Projects whose unmodified `xcodebuild` run previously failed with `xcresult summary unavailable (xcodebuild exit 143)` now get verdicts.
