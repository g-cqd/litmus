# litmus 0.4.8 (from 0.4.5)

Adds four standard-tier mutation capabilities (compound-assignment arithmetic, type-preserving range boundary shifts, unary negation removal outside conditions, and nil-coalescing fallback replacement), explicit opt-in SwiftUI leaf view-element removal (`remove-view-element`) with separate Logic / UI score reporting, and skipped-site visibility in Markdown reports.

## Behaviour

- `replace-arithmetic` now also mutates compound assignment operators (`+=` ↔ `-=`, `*=` ↔ `/=`, `%=` → `*=`), skipping string and array literal appends on `+=`.
- `replace-range` shifts range upper bounds (`a..<b` → `a..<((b) + 1)`, `a...b` → `a...((b) - 1)`) while preserving `Range` vs `ClosedRange` types in ternary schemas and skipping `switch` case patterns.
- `remove-negation` removes unary `!` outside direct `if`/`guard`/`while`/ternary conditions (already covered by `negate-condition` and `swap-ternary`).
- `replace-nil-coalescing` replaces `a ?? b` with `b`, skipping `Never`-returning fallbacks (`fatalError`, `preconditionFailure`, `assertionFailure`).
- `remove-view-element` skips leaf SwiftUI view-builder elements (skipping container wrappers like `Section`/`VStack` to avoid double-counting parent + children and skipping action closures).

## Findings that may appear

With `--operator-tier standard` or `experimental`, newly discovered `replace-range`, `remove-negation`, `replace-nil-coalescing`, and compound-assignment sites may surface previously undetected survivors (for example untested `ClosedRange` upper bounds).
