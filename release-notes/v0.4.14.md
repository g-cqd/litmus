# litmus 0.4.14 (from 0.4.13)

Adds a fast inner loop for developers and coding agents (`--only-id`, out-of-source acceptance of equivalent mutants, `analyze --format agent`, `litmus agent-guide`), mutation of the code a test edit affects (`--include-test-changes`), a synthesized scheme that tests every unit-test target of an Xcode workspace with quarantine of targets that fail unmutated, `litmus clean`, and run-tokenized schema variables; turns per-test reach on by default. Builds on analyzerkit's new `AcceptanceFile`, `LineIndex.excerpt`, `AgentGuide`, `TestDeclarationScanner`, `XcodeNativeTargets` and `XcodeSchemeWriter`.

## Flags

- `run --only-id SELECTOR` (repeatable): a mutant id, an id prefix of 8+ hex digits, or `path:line[:operator]`; always executed, never reused.
- `run --verify-accepted`; `--accepted-file FILE` on `plan` and `run`.
- `run --per-test-reach` is now the default; `--no-per-test-reach` turns it off. `--per-test-reach` still parses.
- `--include-test-changes` (with `--diff` or `--diff-base`) on `plan`, `run` and `analyze`.
- `--all-test-targets` and `--include-ui-tests` (instead of `--scheme`, with `--project`); `run --skip-failing-targets`.
- `analyze --format agent` and `--domain logic|ui|all`.
- New commands: `accept`, `unaccept`, `agent-guide [--install] [--target agents|claude|agents-md]`, `clean [--simulators] [--run DIR] [--dry-run]`.

## Configuration

Optional `acceptedFile` in `.litmus.json` (default `.litmus-accepted.json` at the root). The acceptance file itself is analyzerkit's `AcceptanceFile`, `schemaVersion` 1.

## Cache

Unchanged (`inactive-schema-baseline/v5`). Closure reuse keys now leave out the test files of targets that do not cover a mutant's file when test-target selection is on; with the new tool version, every earlier record misses once.

## Behaviour

- Schemas and test processes name their variables `LITMUS_ACTIVE_ID_<token>`, `LITMUS_COVERAGE_DIR_<token>` and `LITMUS_TEST_TRACE_<token>`, the token being the first 8 hex digits of the SHA-256 of the canonical subject root: a subject whose tests run Litmus never hands the outer selection to the inner run.
- Per-test reach is on by default; a narrowed survivor is still rechecked against every covering test module, so an XCTest-only kill is never lost (regression test with a mixed XCTest and Swift Testing package).
- `--only-id` plans only the selected mutants, so only their files are rewritten; their stored or resumed verdicts are not reused and the store entry is overwritten.
- Accepted mutants are suppressed at planning, matched by id, then by anchor (path, declaration, operator, whitespace-collapsed original and replacement).
- `--include-test-changes`: per changed test file, the mutants its changed Swift Testing tests reached in `--reach-from`'s run when every changed line is inside such a test; otherwise, and for deleted test files, every site of the production files its test targets cover.
- `--all-test-targets` writes `__LitmusAllUnitTests` into the workspace copy only (refused in place). On the ExampleApp fixture (iPhone 18 Pro, iOS 27.2) it gives the same verdict for every mutant as the project's own scheme.
- `--skip-failing-targets` reruns the baseline without the module whose bundle failed, one module at a time (at most 64), and skips quarantined modules in every later run (`-skip-testing:` for `xcodebuild`).
- A `--destination` naming no available simulator lists the available ones (name, iOS version, id; newest first).
- Mutant ids use analyzerkit's `Fingerprint.normalized`; same algorithm, same ids.

## Not in this release

The in-process shared-session execution (`--shared-process`, an `mmap` control page and a helper that runs many mutants in one loaded test process) is not implemented yet.

## Findings that may appear

- Survivors and uncovered mutants in production code a pull request's test edits affect, with `--include-test-changes`.
- `stale-missing` and `stale-killed` notes for acceptance entries.

## Findings that may disappear

- Mutants accepted in `.litmus-accepted.json` (suppressed, as with `// @lm:accept`).

## Consumer steps

- Scripts passing `--per-test-reach` need no change; pass `--no-per-test-reach` to keep the 0.4.13 behaviour.
- Verify downloaded release archives with `shasum -a 256 -c` and `gh attestation verify <archive> --owner g-cqd`.
- Locks that list litmus (swift-ci's built-in tool lock): litmus 0.4.14 by version and SHA-256.
- Projects that pin the litmus `.binaryTarget`: this release's bundle and checksum.
