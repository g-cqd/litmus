# litmus 1.1.0 (from 1.0.1)

`litmus mcp` now runs on AemiMCP, which raises the minimum macOS to 15.6. Two `xcodebuild` fixes are included. The 1.0.2 and 1.0.3 tags were never published; their changes ship here ([1.0.2 notes](v1.0.2.md), [1.0.3 notes](v1.0.3.md)).

## Behaviour

- `litmus mcp` is served by AemiMCP:
  - protocol version negotiation across the four MCP versions, and `notifications/cancelled`;
  - strict JSON-RPC: batches and non-object `params` are refused;
  - typed tool schemas and results.

  The four tools (`litmus_plan`, `litmus_run`, `litmus_gaps`, `litmus_accept`) and their inputs are unchanged, and requests are still served one at a time, in order.
- Under `xcodebuild`, the memory limit no longer applies (from 1.0.2). It covers only `xcodebuild`'s own session, not the simulator's test hosts, so it could not catch a mutant. It only stopped `xcodebuild` as the suite's output grew, which failed unmodified runs with `xcodebuild exit 143`.
- `xcodebuild` result summaries with known issues (`withKnownIssue`, `XCTExpectFailure`) are accepted, expected failures counting as passed (from 1.0.3). They had failed the unmodified run with `xcresult summary unavailable (xcodebuild exit 0)`.
- When a result bundle has no summary, the error says why the run's supervision stopped it, if it did.

## Consumer steps

- Machines on macOS 15.0–15.5: update macOS, or stay on litmus 1.0.1.
- MCP clients: no change. Clients that sent JSON-RPC batches now get an error and must send one request per message.
- Verify downloaded release archives with `shasum -a 256 -c` and `gh attestation verify <archive> --owner g-cqd`.
- Locks that list litmus (swift-ci's built-in tool lock): litmus 1.1.0 by version and SHA-256.
- Projects that pin the litmus `.binaryTarget`: this release's bundle and checksum.
