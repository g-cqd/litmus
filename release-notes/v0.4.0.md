# litmus 0.4.0 (from 0.3.2)

Opt-in operator tiers, parallel simulator execution, numeric score gates, and a more forgiving control check. The default run mutates exactly what 0.3.2 mutated.

## Report

`policy.operators` lists the rule identifiers mutated (absent in older artifacts: the stable tier). New rule ids: `replace-relational`, `flip-boolean`, `replace-arithmetic`, `remove-call`. The `version` is 0.4.0.

## Cache

The execution policy is `v5`: stores, shards and artifacts of 0.3.x are not mixed with 0.4 results. A mutant's identifier depends on its operator, so a stored verdict is never reused for another operator.

## Behaviour

- Destinations written as `name=...,OS=...` are resolved to a simulator identifier; the simulator helper is now used for them.
- An inactive control that fails is retried once and then bisected; before, one failing mutant made every mutant of its batch an infrastructure error.
- Xcode runs stop at the first failing test shown by the result stream, delete result bundles after reading their summary, and pin the architecture for simulator builds. Generated schemas begin with `// swiftlint:disable all`.
- A package depending on local packages outside the root is refused up front with the command to run.
- Mutants run longest-first when an earlier run recorded durations.
- `remove-call` leaves alone the last statement of a `guard` else and of an `if` or `switch` used as a value; the new operators leave attribute arguments and enum cases alone, while the stable ones mutate exactly what 0.3.2 did.
