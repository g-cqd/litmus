# 2026-11-02 — Investigation of extent and thoroughness; fcheck pilot

User asked how far mutations can go and how thorough a run can be.

- Fetched the operator pages of Stryker, PIT, cargo-mutants and muter; read swift-mutation-testing's operator
  campaign (kill, unviable, reviewed-equivalent rates) and its equivalence review file.
- Added `litmus census`: one syntax pass counting 33 candidate operator kinds in production files, by schema shape,
  with statement sites inside result builders counted apart. Ran it on the app and six family packages (`docs/research/census`).
- Shape probes: 27 placements of the standard and extended tiers' shapes compile to object code together for the iOS 18
  Simulator in three modes; four predicted failures fail. Methodological lesson: `-typecheck` misses "missing return",
  which SIL reports; probes compile with `-c`.
- Pilot: Litmus on fcheck (206 mutants). First attempt: baseline failed, correctly stopping the run, because fcheck's
  CLI tests run `<package>/.build/debug/fcheck` and Litmus built elsewhere. Fixed (scratch in the workspace's `.build`).
- Second attempt finished in 1384 s: 126 killed, 25 timeout, 6 survived, 6 no coverage, 43 infrastructure errors. 39 of
  those were "timed out, then timed out without activation": reruns ran among the parallel workers, against what ADR 0005
  stated, with a deadline derived from a baseline measured alone. Fixed: reruns form a serial pass after each batch;
  the first run among workers gets twice the deadline. A unit test now checks the rerun order and deadlines.
- A hypothesis that CLI child processes lose the activation environment was checked and rejected: fcheck's `Process`
  inherits the environment, and a site of the executable survived after activation.
- Report: `docs/research/2026-11-02-mutation-extent-and-thoroughness.md`.
